| 项目 | 内容 |

| 文档版本 | v1.7 |
| 适用范围 | 3PL 仓库盲盘工作包、PDA 作业、PDA 复核及库存重建 |

## 1. 引言

### 1.1 目的

本文档定义盲盘模块的软件需求，供开发、测试、验收使用。

### 1.2 范围

本文档覆盖：

- 盲盘工作包（Work Package）创建与管理
- 盲盘单（Blind Count）创建与管理
- 重盘（Recount）
- PDA 盲盘作业
- PDA 复核
- 盲盘明细记录（含批次产品、序列号产品与无追踪产品）
- 盲盘结果审核
- 库存重建（分两步：库存清除、按审核结果入库）
- 库存重建回滚（两步各自可回滚）

本文档不覆盖：

- 标准盘点流程（非盲盘）
- 库位管理配置
- 产品主数据维护
- PDA 硬件配置
- 客户合同与计费

| 术语 | 说明 |
|---|---|

| 盲盘单 | Blind Count，一次实际盘点，对应一个货位 |
| 重盘 | Recount，复核不通过后发起的新一轮盘点 |
| 轮次 | Round，同一货位的盘点轮次，从 1 开始 |

| lot_name | 批次号或序列号的文本表示，盲盘阶段不关联主数据 |

| 序列号 | 按序列号管理的产品唯一标识，对应库存系统中的序列号主数据 |
| 托盘码 | 托盘条码，文本记录，不关联库存模型 |

| 入库 | 库存重建 Step 2，按审核通过的盲盘结果重新入库 |
| 回滚 | 通过反向库存移动抵消已执行的库存清除或入库 |
| PDA 复核 | 由另一名库管对盲盘结果进行抽样校验 |
| 主管审核 | 主管对盲盘结果做业务授权，决定是否作为库存重建依据 |
| PDA | 带条码扫描头的手持终端 |
| 3PL | 第三方物流 |

## 2. 总体描述

### 2.1 背景

本项目面向 3PL 仓库。3PL 按客户（产品大类）管理库存，盘点时以客户为单位进行盲盘。

仓库盘点时，若盘点人能看到系统账面数量，容易产生「照抄账面」的行为，导致盘点结果失真。为解决该问题，需要一套盲盘机制：盘点人在看不到任何账面数据的前提下，通过 PDA 记录实际盘到的实物。

3PL 场景下，一个客户通常有多个货位。为统一管理同一客户多个货位的盘点作业，引入**工作包**作为顶层业务对象：一个工作包对应一个产品大类（客户），可包含该客户多个货位的盲盘单。

盲盘完成后，不采用「逐行差异调整」的方式，而是采用「库存重建」：将盘点范围内原账面库存全部清除，审核盲盘结果后，按盲盘结果重新入库。库存重建分两步执行，每步均可回滚。

### 2.2 目标

1. 以工作包为顶层对象，统一管理同一客户多个货位的盲盘作业。
2. 盲盘过程中，盘点人只能记录实际盘点结果，不能获取任何账面信息。
3. 盲盘阶段完全不读写库存数据。
4. 盲盘结果作为独立数据保存，后续由单独的处理环节完成库存重建。
5. 支持批次产品、序列号产品和无追踪产品的混合盘点。
6. 现场作业必须通过 PDA 完成，支持条码扫描和二维码批量扫描。
7. 批次和序列号在盲盘阶段统一用 `lot_name` 文本存储，重建时按「产品 + lot_name」匹配或新建主数据。
8. 库存重建分两步执行，每步独立且可回滚。
9. 支持可选的 PDA 复核，由另一名库管执行，允许异常并记录异常。
10. 复核不通过时，通过重盘（Recount）产生新盲盘单，不修改历史盲盘结果。

### 2.3 用户角色

| 角色 | 说明 | 使用模块 |
|---|---|---|
| 盘点员 | 现场执行盲盘 | PDA 盲盘模块 |
| 复核员 | 现场执行复核 | PDA 复核模块 |
| 仓库主管 | 创建工作包、审核盲盘结果、执行库存重建与回滚 | 后台 + 处理模块 |
| 管理员 | 全部权限 | 全部 |

### 2.5 设计约束

| 编号 | 约束 |
|---|---|
| C1 | 盲盘阶段禁止读写库存数量、库存余额、库存移动、库存预留及现有库存序列号状态 |
| C2 | 盲盘阶段允许读取产品主数据和库位主数据，用于条码识别和货位校验 |
| C3 | 批次和序列号在盲盘阶段统一用 lot_name 文本存储 |
| C4 | 盲盘阶段不查询、不创建批次或序列号主数据 |
| C5 | 库存重建只发生在处理模块的确认环节 |
| C6 | 盲盘结果一旦完成不可修改 |
| C7 | 盘点必须通过 PDA 执行，后台表单不作为现场作业入口 |
| C8 | 扫描顺序固定：货位号 → 托盘号 → 产品号 → lot_name → 数量 |
| C9 | 一个盲盘单对应一个货位，明细行不需要货位 |
| C10 | 产品条码扫描不到时，必须阻断，不允许跳过 |
| C11 | 产品不属于当前工作包的产品大类时，必须阻断 |
| C12 | 工作包必须由仓库主管或管理员创建 |
| C13 | 一个工作包只对应一个产品大类 |
| C14 | 一个工作包下的多个盲盘单属于同一产品大类（客户） |
| C15 | 库存重建分两步：Step 1 库存清除，Step 2 按审核结果入库 |
| C16 | 重建时按「产品 + lot_name」匹配批次或序列号主数据，匹配不到则新建 |
| C17 | 库存汇总键：无追踪产品按产品；批次或序列号产品按产品 + lot_name；托盘不进入库存维度 |
| C18 | 两步独立执行，Step 2 必须在 Step 1 完成后执行 |
| C19 | 两步各自可回滚 |
| C20 | 回滚通过反向库存移动实现，不删除原记录 |
| C21 | 回滚按步骤整体执行，不支持部分回滚 |
| C22 | Step 1 回滚前，必须先回滚 Step 2（如有） |
| C23 | 回滚必须记录回滚人、时间、原因 |
| C24 | 只有仓库主管或管理员可以执行回滚 |
| C25 | lot_name 输入状态下，每次扫描先按条码查产品主数据 |
| C26 | Serial 在存在冲突的未完成盲盘任务中不得重复 |
| C27 | Lot 允许存在于不同货位 |
| C28 | 已处理完成的盘点单不参与唯一性判定 |
| C29 | 复核阶段校验比盲盘阶段宽松，允许异常并记录异常 |
| C30 | 工作包进入 done 的条件是所有库存重建完成 |
| C31 | 工作包在 done 之后不可再添加新的盲盘单 |
| C32 | 复核不通过时，通过重盘产生新盲盘单，不修改历史盲盘结果 |
| C33 | 一个货位在同一轮次只能存在一个进行中的盲盘单 |
| C34 | 一个货位最终只能有一个有效处理单 |
| C35 | 允许空盘（零明细），最终库存为 0 |

### 2.6 设计原则

| 编号 | 原则 | 说明 |
|---|---|---|
| P1 | 盲盘不碰库存 | 盲盘阶段禁止读写任何库存数据 |
| P2 | 盲盘不碰主数据 | 批次和序列号仅以文本记录，不关联主数据 |
| P3 | 盲盘不显示账面 | 界面不显示账面数量、差异、预期 lot_name |
| P4 | 职责分离 | 盲盘记录、复核、结果审核、库存重建是独立环节 |
| P5 | 结果可追溯 | 每条记录需记录盘点人、盘点时间 |
| P6 | 条码强校验 | 产品条码查不到或产品超出范围时阻断 |
| P7 | 客户维度 | 盘点以产品大类（客户）为单位 |
| P8 | 两步重建 | 库存重建分两步执行，每步独立 |
| P9 | 可回滚 | 每步通过反向库存移动回滚，不删除原记录 |
| P10 | 不可重复 | 每步在未回滚前不可重复执行 |
| P11 | 结果不可修改 | 盲盘结果一旦完成不可修改，重盘产生新盲盘单 |
| P12 | 复核宽松 | 复核允许异常，记录异常，不阻断 |
| P13 | 工作包边界 | 一个工作包只对应一个产品大类 |
| P14 | 工作包权限 | 工作包只能由主管或管理员创建 |
| P15 | 唯一有效处理 | 一个货位最终只能有一个有效处理单 |

### 2.7 假设

| 编号 | 假设 |
|---|---|
| A1 | 产品主数据已维护，条码可用于扫描 |
| A2 | 库位结构已配置，货位有条码 |
| A3 | 批次和序列号在实物上可读取 |
| A4 | PDA 扫描头以键盘输入 + 回车方式工作 |

| A8 | 库存清除和入库可通过反向库存移动回滚 |

## 3. 业务流程

### 3.1 对象层级

```
工作包（Work Package）
├── 产品大类（Category）
│   └── 客户（Customer，自动带出）
│
├── 盲盘单 #1 → 货位 A（round 1）
├── 盲盘单 #2 → 货位 B（round 1）
├── 盲盘单 #3 → 货位 C（round 1）
└── 盲盘单 #4 → 货位 A（round 2，重盘）
        │
        ▼
   处理单 #1 → 货位 A（对应盲盘单 #4）
   处理单 #2 → 货位 B（对应盲盘单 #2）
   处理单 #3 → 货位 C（对应盲盘单 #3）
        │
        ▼
   Step 1 库存清除（可回滚）
   Step 2 入库（可回滚）
```

### 3.2 总体流程

```
主管创建并启动工作包
        ↓
盘点员执行盲盘（PDA）
        ↓
盲盘完成（round 1）
        ↓
（可选）PDA 复核
        ├── 不通过 → 主管决定
        │             ├── 接受当前结果
        │             └── 发起 Recount（新盲盘单，round + 1）
        └── 通过 ↓
主管审核盲盘结果
        ↓
库存重建 Step 1：库存清除（可回滚）
        ↓
库存重建 Step 2：按审核结果入库（可回滚）
        ↓
工作包内所有库存重建完成
        ↓
工作包 done
```

### 3.3 PDA 盲盘作业流程

```
进入工作包
    ↓
选择货位 → 创建或继续盲盘单
    ↓
扫货位码 ──不一致──> 报错，重扫
    ↓
扫托盘码（可选）
    ↓
扫产品码 ──查不到──> 阻断
         ──超出产品大类──> 阻断
    ↓
├─ 序列号管理 ──> 扫序列号
│                  ├─ 单个 SN ──> 重复校验 ──> 生成 1 行
│                  └─ 二维码（多 SN）──> 原子校验 ──> 生成 N 行
│
├─ 批次管理 ──> 输入 lot_name ──> 输入数量 ──> 生成/累加 1 行
│
└─ 无追踪 ──> 输入数量 ──> 生成/累加 1 行
    ↓
是否继续？──是──> 回到「扫托盘码 / 扫产品码」
    ↓ 否
完成盘点 ──> 盲盘单 done
```

### 3.4 PDA 复核流程

```
选择盲盘单
    ↓
扫货位码 ──不一致──> 阻断
    ↓
扫托盘码（不存在不阻断）
    ↓
扫产品码（不存在不阻断）
    ↓
判断产品追踪方式
    ├── 序列号管理 ──> 抽检扫描序列号（匹配不到不阻断）
    └── 非序列号管理 ──> 录入检查数量（不匹配不阻断）
    ↓
生成复核记录
    ↓
填写复核结论
```

### 3.5 重盘流程

```
盲盘单 #001（round 1）
    ↓
done
    ↓
复核 failed
    ↓
主管决定
    ├── 接受当前结果 → 进入处理流程
    └── 发起 Recount ↓
              ↓
        盲盘单 #002（round 2，新单）
              ↓
        盘点员执行
              ↓
        盲盘单 #002 done
              ↓
        复核（可选）
              ↓
        主管审核
              ↓
        库存重建
```

**注意：** #001 保持不变，#002 是新单，两者独立。

### 3.6 库存重建流程

```
处理单.approved
    ↓
执行 Step 1：库存清除
    ↓
清除状态：done
    ↓
执行 Step 2：按审核结果入库
    ↓
入库状态：done
    ↓
处理单.done
```

**回滚流程：**

```
Step 2 已执行
    ↓
回滚 Step 2 → 入库状态：rolled_back
    ↓
（可选）重新执行 Step 2
    ↓
（可选）回滚 Step 1 → 清除状态：rolled_back
    ↓
（可选）重新执行 Step 1
```

**状态恢复语义：**

```
Initial
   ↓
Step 1（库存清除）
   ↓
Cleared
   ↓
Step 2（入库）
   ↓
Rebuilt

回滚 Step 2 → 恢复到 Cleared
回滚 Step 1 → 恢复到 Initial
```

### 4.3 PDA 盲盘前端交互

#### 4.3.1 PDA 入口

```
PDA 首页
├── 我的工作包（进行中）
│   ├── WP-001 / 客户 A / 产品大类 A
│   │   ├── 货位 A-01 [未开始]
│   │   ├── 货位 A-02 [进行中]
│   │   └── 货位 A-03 [已完成]
│   └── WP-002 / 客户 B / 产品大类 B
└── 新建工作包（仅主管权限）
```

#### 4.3.2 扫描顺序与状态推进

| 步骤 | 输入 | 说明 |
|---|---|---|
| 1 | 货位码 | 必须与盲盘单货位一致 |
| 2 | 托盘码 | 可选，可跳过 |
| 3 | 产品码 | 识别产品，查不到或超出范围则阻断 |
| 4 | lot_name 或 数量 | 按产品追踪方式决定 |
| 5 | 提交明细行 | 生成或累加明细 |
| 6 | 回到步骤 2 或 3 | 继续下一轮 |

**规则：**

| 编号 | 规则 |
|---|---|
| R1 | 未扫货位码前，其他扫描一律拒绝 |
| R2 | 货位码必须与盲盘单绑定的货位一致 |
| R3 | 产品条码查不到时，阻断并报错 |
| R4 | 产品不属于当前工作包的产品大类时，阻断并报错 |
| R5 | 扫产品码时，若当前有未提交的 lot_name 输入，先提交当前产品 |
| R6 | 序列号产品：数量固定为 1，不允许修改 |
| R7 | 批次产品：允许输入批次号和数量 |
| R8 | 无追踪产品：允许输入数量，默认 1 |

#### 4.3.3 扫描货位码

- 校验货位是否存在
- 校验货位是否与盲盘单绑定货位一致
- 一致则允许进入下一步，否则报错并拒绝

**界面要求：** 显示工作包号、客户、产品大类、货位名称、已扫货位码。

#### 4.3.4 扫描托盘码

- 托盘码作为当前扫描上下文的标签，记入明细行的托盘码字段
- 不校验托盘是否存在，不查库存
- 允许跳过
- 切换托盘时，后续明细归属新托盘

#### 4.3.5 扫描产品码

- 按条码识别产品
- 查不到 → 阻断
- 产品存在但不属于当前工作包的产品大类 → 阻断
- 识别到产品后，按追踪方式切换输入焦点

**错误提示区分：**

| 场景 | 提示 |
|---|---|
| Barcode 不存在 | 无法识别产品条码，请重新扫描 |
| 产品存在但超出范围 | 该产品不属于本次盘点范围 |

#### 4.3.6 lot_name 输入状态下的产品码识别

**在 `SCAN_SERIAL` / `SCAN_LOT` 状态下，每次扫描先按条码查产品主数据：**

```
扫描输入 X
    ↓
用 X 查产品主数据
    ↓
├── 查到，且属于当前工作包的产品大类
│       → 视为产品码
│       → 结束当前产品的 lot_name 连续扫描
│       → 切换到新产品
│
├── 查到，但不属于当前工作包的产品大类
│       → 阻断「该产品不属于本次盘点范围」
│
└── 查不到
        → 视为 lot_name
        → 生成明细行
        → 继续当前产品的 lot_name 输入
```

**规则：**

| 编号 | 规则 |
|---|---|
| R9 | lot_name 输入状态下，每次扫描先按条码查产品主数据 |
| R10 | 查到且属于当前工作包的产品大类 → 视为产品码，切换产品 |
| R11 | 查到但不属于当前工作包的产品大类 → 阻断 |
| R12 | 查不到 → 视为 lot_name，生成明细行 |
| R13 | 切换产品后，原产品的 lot_name 连续扫描结束 |
| R14 | 不按条码格式判断，只按产品主数据查询结果判断 |
| R15 | 产品条码查询可使用前端缓存，缓存范围限定当前工作包 |

#### 4.3.7 扫描序列号（序列号产品）

##### 4.3.7.1 连续扫描（单个序列号）

- 当前必须有已识别的序列号管理产品
- 每扫一个序列号，先做重复校验，通过后生成一行明细
- 序列号以文本记录，不查询、不创建序列号主数据
- 数量固定为 1
- 提交后继续等待下一个序列号

##### 4.3.7.2 二维码批量扫描（逗号分隔）

- 当前必须有已识别的序列号管理产品
- 按英文逗号拆分二维码内容
- 拆分后去除空白，空字符串忽略
- 每个序列号生成一行明细，数量固定为 1
- 若拆分后数量为 0，报错
- **批量解析和校验必须完整完成后，才生成明细；任何一个序列号不符合规则时，整次扫描不得产生部分明细**
- 批量创建后，继续等待下一个序列号

#### 4.3.8 输入批次和数量（批次产品）

- 当前必须有已识别的批次管理产品
- 批次号以文本记录，不查询、不创建批次主数据
- 数量必须大于 0
- 同一产品 + 同一托盘 + 同一 lot_name，累加到同一行
- 无匹配行时新建一行
- 提交后回到产品码输入

#### 4.3.9 输入数量（无追踪产品）

- 当前必须有已识别的无追踪产品
- 数量必须大于 0
- 同一产品 + 同一托盘，累加到同一行
- 无匹配行时新建一行
- 提交后回到产品码输入

#### 4.3.10 lot_name 唯一性

**Serial 唯一性：**

| 编号 | 规则 |
|---|---|
| R16 | 同一产品的同一 Serial 在「未处理完成」的盲盘明细中不得重复 |
| R17 | 判定跨盲盘单、跨货位、跨托盘、跨工作包 |
| R18 | 已处理完成的盘点单不参与判定 |
| R19 | cancel 状态的盘点单不参与判定 |
| R20 | 被替代的盲盘单不参与判定 |

**Lot 唯一性：**

| 编号 | 规则 |
|---|---|
| R21 | 同一产品的同一 Lot 允许存在于不同货位 |
| R22 | 同一盲盘单内，同一产品 + 同一托盘 + 同一 Lot 累加到同一行 |

**通用：**

| 编号 | 规则 |
|---|---|
| R23 | 重复扫描时阻断，不生成明细行 |
| R24 | 阻断提示：「该序列号已被盘点，请勿重复扫描」 |
| R25 | 阻断后焦点保持在 lot_name 输入 |
| R26 | 批量二维码内出现重复 Serial 时，整次拒绝 |
| R27 | 批量二维码内的 Serial 与已扫明细重复时，整次拒绝 |
| R28 | 批量扫描不允许部分成功 |
| R29 | 唯一性判定只查盲盘明细，不查主数据，不查库存 |
| R30 | 撤销后，被撤销的 Serial 可重新扫描 |

#### 4.3.11 撤销机制

- PDA 提供「撤销上一条」用于现场误扫
- 撤销只删除最近一条有效扫描
- 不提供任意明细编辑
- 如需作废历史行，由主管在后台作废并记录原因

**禁止显示：**

**必须提供：**

**动作：**

| F6.4 | 清除必须可回滚 |
| F6.5 | 清除回滚后，库存恢复到执行清除前的状态 |

#### 4.5.5 库存重建 Step 2：按审核结果入库

**范围：**

- 来源：该货位已审核通过的盲盘结果
- 按货位入库

**动作：**

- 按审核通过的明细重新入库

**功能要求：**

| F6.10 | 托盘不进入库存维度 |
| F6.11 | 按（产品, lot_name）匹配主数据，匹配不到则新建 |
| F6.12 | 入库必须记录库存移动 |
| F6.13 | 入库成功后，入库状态变为 done |
| F6.14 | 入库必须可回滚 |
| F6.15 | 入库回滚后，库存恢复到执行入库前的状态 |

#### 4.5.6 两步独立性与回滚

**功能要求：**

| 编号 | 要求 |
|---|---|
| F6.16 | 两步独立执行，Step 2 必须在 Step 1 完成后执行 |
| F6.17 | Step 1 必须可回滚 |
| F6.18 | Step 2 必须可回滚 |
| F6.19 | 回滚通过反向库存移动实现，不删除原记录 |
| F6.20 | 回滚按步骤整体执行，不支持部分回滚 |
| F6.21 | Step 1 回滚前，必须先回滚 Step 2（如有） |
| F6.22 | 回滚必须记录回滚人、时间、原因 |
| F6.23 | 只有仓库主管或管理员可以执行回滚 |
| F6.24 | 回滚后，处理单回到 approved，对应步骤状态回到 pending |
| F6.25 | 回滚后，允许重新执行对应步骤 |
| F6.26 | 每步在未回滚前不可重复执行 |
| F6.27 | 重新执行必须基于当前有效的上游状态，不能修改已冻结的盲盘事实 |
| F6.28 | 若盲盘结果有误，走 Recount，不修改原结果 |

**回滚状态恢复：**

```
Initial
   ↓ Step 1
Cleared
   ↓ Step 2
Rebuilt

回滚 Step 2 → Cleared
回滚 Step 1 → Initial
```

## 10. 附录

### 10.1 状态流转

**工作包：**

```
draft ──> in_progress ──> done
   │           │
   └───────────┴──> cancel
```

**盲盘单：**

```
draft ──> counting ──> done
   │           │
   └───────────┴──> cancel
```

**复核单：**

```
draft ──> counting ──> done
```

**处理单：**

```
draft ──> review ──> approved ──> processing ──> done
   │          │
   └──────────┴──> cancel
```

**处理单步骤状态：**

```
清除：pending ──> done ──> rolled_back
入库：pending ──> done ──> rolled_back
```

### 10.2 完整流程

```
主管创建工作包（draft）
    ↓
主管启动工作包（in_progress）
    ↓
盘点员创建盲盘单（round 1，draft）
    ↓
盘点员扫货位码（counting）
    ↓
盘点员完成盲盘（done）
    ↓
（可选）复核单
    ├── 不通过 → 主管决定
    │             ├── 接受 → 继续
    │             └── 发起 Recount → 新盲盘单（round 2）
    └── 通过 ↓
主管审核（review）
    ↓
主管确认（approved）
    ↓
执行 Step 1：库存清除（processing）
    ↓
清除状态：done
    ↓
执行 Step 2：入库（processing）
    ↓
入库状态：done
    ↓
处理单.done
    ↓
工作包内所有有效处理单完成
    ↓
工作包.done
```

**回滚流程：**

```
Step 2 已执行
    ↓
回滚 Step 2（rolled_back）→ 库存恢复到 Cleared
    ↓
（可选）重新执行 Step 2
    ↓
（可选）回滚 Step 1（rolled_back）→ 库存恢复到 Initial
    ↓
（可选）重新执行 Step 1
```
